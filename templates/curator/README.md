# `curator@1.15.3`

The window of one model, owned in one place, with a ledger of every call. Contract tables only; the prose follows with the program it belongs to.

Since 1.1.0 ([#892](https://github.com/mmeyerlein/meclaw/issues/892), [#893](https://github.com/mmeyerlein/meclaw/issues/893), [#895](https://github.com/mmeyerlein/meclaw/issues/895), [#896](https://github.com/mmeyerlein/meclaw/issues/896)) the window follows a role (`role`: `talky`,
`consult`, `coding`, `research`), foreign words and tool results stand behind a short id
`[#<12 hex>]` the model can release or pin through the `window` section of its answer, another hive
can pin a text into the window (`in_pin`), and the hive answers the collector's menu question itself
(`./schemas`). Three cells joined it: `./history` answers the `history_*` tools out of the ledger,
`./push` builds the memory leg's question and looks a `gap` up after the answer, and `./handover`
hands a new session a note on the last one and a renewed duplex call a block of the recent
conversation. Lanes joined the boundary, so it is the second digit.

Since 1.1.1 ([#904](https://github.com/mmeyerlein/meclaw/issues/904)) the cache clock is one standing order under a fixed id per hive (per round since GH #943),
re-armed on every call (`add` with `rearm`), so the timer keeps one row for it instead of one
per call. No lane moved; a promise is repaired, so it is the third digit.

## Lanes (into the hive path, on `hop.route`)

| Lane | From | Carries |
|---|---|---|
| `in_curate` | the context collector | `messages[]` the whole running round (opening turn, evidence pairs, every tool iteration so far), never history; `system` the per-round slots; `tool_scope` if set; `hop.session_id`, `hop.turn_id`, `hop.iter` and whatever else the caller puts on the call (no session = `default`, no turn = a round of its own). An `assistant` text in a round without a tool call of its own (a duplex turn pair; the evidence pairs `memory_recall` and `affinity_brief` do not count) is a final answer and an episode. Answered by one `brain`. |
| `in_slots` | the context collector | `system` only (tool menu, sidecar contract). Kept as the collector's slots, sent with the next call whose system changed; no call of its own. |
| `in_llm` | the tap: every output of the model | the raw output with `hop.finish_reason`, `hop.model`, `hop.tokens_*`, `hop.cost`, `hop.cache_expires_at`, `hop.context_window`, the answering model's limits and prices `hop.input_soft`, `hop.input_hard`, `hop.cost_in`, `hop.cost_cached_in` (GH #1038, absent from an old package), and `context.curator_call`, `context.session_id`, `context.turn_id`, `context.iter`. A final answer (`stop`, `length`) enters the wall from here; the sentence beside a tool call (`tool_calls`) enters as an interim answer, not final, never an episode. Without a session it is session `default`, without a turn the round of its call (the rule of `brain`); without `context.curator_call` it is dropped and said on stderr. |
| `in_pack` | an identity pusher | `system.{identity,identity_short,persona,handover,instructions}` (or `slot` + `content`); the context rides on to `pack_ack` untouched. |
| `in_close` | the session keeper | `context.session_id` of the closed session; `context.audience_set` the round its generation was opened in, the only round the `write` batch is gated by. |
| `in_model` | the llm-registry | a params-only body for `./summarizer`, only when `hop.subscriber` names it (the one model door of the hive). |
| `in_section` | the parent's splitter | one section of the sidecar block of an answer of the model (`hop.section`, body `{messages: [], section, payload}`, the answer's context). `window` (`release`/`pin`: block ids) becomes `marks` rows; `gap` goes to `./push` (through `./policy`), which marks it once and looks it up after the answer; `memory` a `topic` mark (`{movement, name}`, movement start/continue/end) and, when `./intake` `pass_sections` names it, leaves again unchanged on `sidecar`. Any other section is dropped and said. A section whose hop carries `sidecar_verify` -- the parent splitter's rule for it, canonical JSON, GH #1079 -- and is none of `window`, `gap`, `things` is checked first and leaves on `sidecar` whatever its name: every item of its array (the rule's `items`, else the first list), each named field word for word against the round's `user`/`peer` turns (`turn`), those and the round's memory bundle (`turn+recall`) or the body's `verify_answer` (`answer`). Both sides casefolded, NFC, curly quotes and dashes folded, whitespace collapsed, punctuation at the edges stripped; the quote stands in one source at word boundaries, under three words only as a whole source; no fuzzy match. A `memory` section is checked only where `pass_sections` hands it on. |
| `in_pin` | another hive | `pins[]`, each `{text, source, until?}`: `source` one path segment, never `model`; `until` RFC 3339. Optional `replace_sources[]` (at most 16, each by the `source` rule): every live pin of those sources ends first (`until` = now, no row deleted), except a hash the new set carries; `pins: []` with it empties those sources. A block of kind `pin` and a `pins` row; the window shows it under `system.pinned.<source>.<id>`. Nothing else of the hive is written through this door. A pin without `context.audience_set` is refused (`missing_audience`, stderr, nothing written). A pin may name its own `audience_set` (GH #972, see below). |
| `in_schemas` | the collector's menu question | `tools[]` the declared names. `./schemas` answers on `tool_schemas` with the curator's tools and sections (`CURATOR_OFFER`). |
| `in_history_call` | the parent's dispatcher, on `hop.tool_name` starting `history_` | one `history_search`, `history_read` or `history_outline` call (GH #893): one `tool_call` turn, the arguments as its text, `hop.tool_call_id`, `hop.tool_name`, the round's context. Answered by one `tool_result` out of this hive's ledger. |
| `in_recall_ask` | the context collector | its per-turn memory ask (route `recall`): `phase`, `turn_id`, `session_id`, `iter`, `recall_query`, `memory_tier`, `recall_window_from`, `recall_window_to`, the person's words as `messages[]`. Answered by exactly one `recall` (`./push`, through `./policy` for the knobs); never held back. |
| `in_gap_bundle` | the memory, through the parent's edge | the answer to a gap's own ask, recognised by `context.gap_ask`; never the collector's. A find becomes an addendum; an empty bundle, a reject or the empty-state sentence is nothing. |
| `in_renewed` | the member, from a duplex channel | a live session of a running call was renewed at its provider's limit (GH #896): `hop.call_id`, `hop.renewal_n`. Answered by one `sidecar` without a model. |
| `in_stats` | an observer, through the parent (GH #926) | a question, all hop: `stats_tag` (1 to 64 characters), `stats_from`/`stats_to` (RFC 3339, `from` counts, `to` does not, at most 31 days), `stats_kinds` (a JSON array as text out of `calls`, `gap`, `reread`, `ask`, `correction`, `tool_error`), `stats_samples` (0 to 50, default 0). Answered by exactly one `stats` out of this hive's ledger, read only. |

A gap's find enters the wall of the session's next round as a `memory_recall` pair whose result opens with `[addendum to your last answer -- looked up after it, for: <gap>]` -- `./push` hands the pair to `./intake`, the wall's one writer, on the internal lane `in_addendum`, once the ledger has answered the write of its `addendum_done`; the ask leaves at once, so the pair races the memory's answer to the round's first turn, and nothing orders the two; its marks are `gap` (the signal), `addendum` (the find, kept) and `addendum_done` (shown, or why not). A find the window already carries is not shown twice, and one for a session that has ended stays unshown. The gap is asked whole -- the memory hive's own query guard cuts a question (GH #1225). Whether a gap is looked up and a find kept is the ledger's word alone: the `gap` and the `addendum` mark are written only if absent, and only the message that wrote one goes on, so a twin -- after a restart of the cell too -- is looked up once and a duplex find is said once (`fact` leaves after its mark); likewise a find is shown only by the ask whose `addendum_done` landed, and a `once` candidate only by the ask whose update found it unused, so two asks in flight show each once. A find whose marks could not be read is held (state `pending:push:gap-<id>` and a mark `held`) and looked at again with the next message of its round: shown then, or closed with a mark `held_done`. No timer.

**Push candidates (`in_candidate`, GH #949).** Another hive -- an installed app, a store of the person's things -- hands the curator texts it wants in the model's window of a later turn: `{source, candidates: [{id, text, audience_set?, triggers?, until?, once?, priority?}], withdraw?: [id]}`. The round is `context.audience_set` of the push and is required (`missing_audience`, nothing written); a candidate without its own `audience_set` takes the round, one with it must stay within the round (every member in the round, `*` only when the round names `*`), else that candidate alone is refused `audience_widened` (a candidate naming `[]` widens every round but `[]` itself); one out of its bounds (at most 32 per body, `id` up to 64 characters, `text` at least 1 character -- no upper bound of its own (R-IG-1), up to 16 `triggers` of up to 64 characters and none of punctuation alone, `priority` 0 to 9, default 5) is refused `invalid_input`, and a repeated `id` counts by its last entry. A kept candidate is a block of kind `candidate` and one `candidates` row per `(source, id)`: a new text, `once` or trigger list starts it afresh, `withdraw` ends it (`until` = now), and one whose `until` has passed is kept and never shown. In its `ask` phase `./push` takes the candidates the round of the ask may see (`covers`, never wider; a round-less ask only `[]` and `*`) that are live, not a used `once`, and either carry no trigger or one the person's words of this turn name as whole consecutive words (NFC, case-folded, a possessive `'s` dropped) -- and not again within `candidate_cooldown` turns (default 5). Best first by `priority`, then the youngest, they reach the model as ONE `memory_recall` pair that `./push` hands `./intake` (`in_addendum`, the road of a gap's find) for the round of the ask -- one with a `once` candidate only after the ledger answered its update, like a find: the call (id `call_candidates_<16 hex>`) asks for the triggers the person's words hit, joined with ", " (empty when none carried one), and the result is the line `[addendum -- notes handed to this conversation for this round; not said by the person]` with the part `[<text>; <text>]` below it, whole candidates within a twentieth of the window this hive serves (every picked one without a known window), the ones left out said behind the part as `...[dropped: <n> candidates (<m> chars) over budget]` and kept for a later turn (`candidate_push` "0" = off); the memory question (`recall_query`) never carries them, so every turn asks exactly as before. One ask reads at most `candidate_rows` candidate rows, best first, and a full page is said on stderr. A colony without the `candidates` table has none: the store's `unknown_table` for that read is an empty one; any other failed read of them names `a-cand` in `recall_degraded`, and the turn goes without candidates (GH #1225). `once` is true by default without triggers and false with them, and a shown `once` candidate is used. A receipt `candidate_ack` `{source, stored, refused: [{id, error_code}]}` leaves only when the push carries `hop.ack` "1": a generation fans one push out to the curator of each of its brains, and receipts nobody asked for would be dead letters. The way back out is the sidecar section `things`, offered only when `things_section` is "1" at `./schemas` and at `./intake` (the instruction is `things_instruction`): `{name, kind?, note?}` entries under `items`, as `./schemas` defines them (no count of its own since GH #1085), checked by `./intake` and handed on as ONE `thing_seen` `{items, turn_id, episode_turn_id?, session_id}` with the round in `context.audience_set` -- never without a round, and never as `sidecar` as well, because the parent's splitter hands `things` to the curator like `window`, `gap` and `memory`.

The model behind the hive orders its system part with `history` after `identity`, `persona` and `instructions` (`system_order`): the summary changes only on a rebuild and stands last. A brain `llm` with `system_writable` behind a curator must allow `history`, `pinned`, `roster`, `consult` and `instructions` -- every call carries them as `$replace` roots.

**The system part of a turn stands (GH #1298).** A brain answers one turn in several calls, one per tool round, and a provider that signs its thinking binds every block to the prefix it was made under (`system`, `tools`, the earlier messages): a replay under another prefix is refused (the native Messages wire answers 400). Two rules keep it. First, the window a call is fitted to is its OWN way's: the tap keeps `input_soft`/`input_hard` of a brain answer under the bare keys and those of any other way under `input_soft:<way>`/`input_hard:<way>` (the way rides with the call's projection `window_est:<call>`; a bridge is quick), so a quick answer no longer cuts the brain's contract, renders its earlier answers or guards its hard line. Second, the FIRST `brain` call of a turn keeps its leaves, the window they were fitted to and the contract cuts it said (`state` `turn_system:<session>:<turn>`), and every later `brain` call of the same turn and round sends exactly those leaves, renders the earlier answers' sidecar blocks under that window and says those cuts -- whatever the window, a slot, a pin or a consult's mark did in between; the next turn takes them as they stand then. One row per running turn: two turns of a session keep their own, the brain's answer that ends the turn takes its row down, and a row a round left (a hand-over, a lost answer) goes with the first brain call of a later turn once it is older than `pending_sweep_s` (every row is entered in the session's list `turn_system_last:<session>` when it is written, an escalated turn's too). `tools` is not frozen: a consult the brain starts in a round denies `consult_cogny` from the next call on, the `llm` cell then asks the provider to drop the replayed thinking instead of refusing, and the `consult.pending` note joins the system with the next turn (within the turn the brain has its own call and result). Measured in production: the quick voice's answers had left its small window in state, the brain's first call cut the contract to it, the brain's own answer stamped a larger one, and the call after the tool result carried the whole contract -- the turn died after its interim sentence.

**The handover (`./handover`, GH #896).** A closed session (`in_close`) leaves a note: its turns go through `./summarizer`, off the hot path, and the answer is kept as a block of kind `summary` with a `marks` row `handover` (state `prepared`); a session that left no turn leaves nothing. The first call of a session this window did not serve last goes from `./policy` through `./handover` once, without a model: a NEW session (no wall row before this round) gets the leaf `history.handover` -- the note of the session served last, when it closed, and the topic still open, each only when the new session's round passes its audience (`state` `handover_audience` keeps the leaf's audience bound to the leaf's hash, and the window shows the leaf only when that hash is the slot's and the round passes the audience) (the `name` of the newest `topic` mark that names one, unless an `end` came after it) -- and the call returns to `./policy` (`handover-done`), which reads its window as for any call: the plan's cover, the rows it holds, every pin. The leaf carries no pins, because the window shows every valid pin already. It stands for the session and falls at the first rebuild after it of the round its audience names (GH #943). A renewed live session (`in_renewed`) sees no system part of this hive, so its block carries it all: the newest `renew_rounds` rounds as text, the summary, the pins, the open commitments (pins with `source` `commitment`) and the topic, at once and without a model. Open commitments stay empty until a hive pins them through `in_pin`; no parent draws that door yet. Every block is at most its share of the window (the window rule below), cut by rank: pins and commitments, then the topic, then the turns, the summary last. The pack family `handover` is the identity pusher's and is never touched; this leaf is `history.handover`, owner `curator`. Since GH #1225 every row the handover keeps -- the parked note, the leaf's slot, `handover_audience`, `handover_for`, `renewed_last:<session>`, `summarizer_input_soft` -- is written in one step (`insert` with `replace` on its key, a block `if_absent` on its hash), so a refused write leaves the old value, never none. Its reads name what they look for, with no count: the newest summary the round may see and the wall above its cover, the newest `topic` mark that says something (however many quiet turns came since), the `handover` marks of the one session in question. A read the ledger refused is never "no rows": the step reads once more, and refused again it ends loudly -- a `store_error` mark, the code in the header -- with no note, no leaf for a returning session, and a renewal block that carries its head only. Whether a session is prepared is decided by a `prepared` mark read from the ledger, never by what the child sent.

## The window per role

`./policy` `role` picks the presets; every knob set on the instance wins. The window is the system part (slots, `pinned.*`, stubs) + the wall after the plan's cover, each block as the plan shows it + the running round. A rebuild (cold cache, a line of the model's package -- below --, or without a package `tokens_prompt` over `compress_at` of the model's own window) makes the plan: segments by `horizon`, their form by `tiers` (`raw`, `summary`, `none`), the newest `keep_recent` rounds and the newest round always raw, the model's pins raw. Over `rebuild_to` of the usable window it shrinks old tool results (outside `keep_rounds`), then stubs tools unused for `stub_tools_after` rounds, then gives the summary up. Between two rebuilds only the end of the window moves.

**No window of a role's own (R-IG-1, GH #1085, since 1.11.3).** The usable window is the catalog row of the answering model: `input_soft`, which the llm cell stamps on every answer (GH #1037), cut only to the model's own reported window. Until 1.11.2 a role capped it (`quality_cap`: talky 120000, consult 80000, coding 70000, research 80000 tokens, GH #892) -- a talky under luna (`input_soft` 250000) kept 120000, handed that to every producer and, on an answer without the row's limits, rebuilt at 60000. Whether a model reads a smaller window well is a question of its catalog row, never a knob of this hive.

**Short ids.** With `short_ids` on, somebody else's words and a tool result begin with `[#<12 hex>] `, the first 12 hex digits of the wall block's hash; the model's own answers and tool calls never do. The model names ids in its `window` section: `release` shows the block as `[#<id> released — history_read("#<id>")]` from the next rebuild on, `pin` keeps it raw below the cover. Identity, persona, instructions and the round the section was said in stay; an unknown id is ignored and said. A block with `valid_until` passed at the plan's time shows as `[#<id> expired]`. The ledger keeps every block byte for byte; a form the window shows is a block of kind `view`.

**Window plan per round (GH #943).** `./policy` keeps one window plan per round, not one per hive: with one plan, a rebuild one round started set the cut, the shrunk results and the stubs of every other round's window. A round's key `round_key` is the first 12 hex digits of the SHA-256 of the canonical round (the JSON array sorted, without duplicates, as `audience_set` carries it); a call without a round has the key of `[]`, and `["*"]` is a round of its own. Under it `state` holds `window_plan:<rk>`, the rebuild claim `rebuild_running:<rk>` (one rebuild per round at a time), `last_call:<rk>`, `armed_call:<rk>`, `actions_pending:<rk>`, `pending:summary:<rk>` and `summary_audience:<rk>`, and `./intake` hands a call on with the plan of its own round. The summary slot is `history.summary:<rk>`, shown to its round as the leaf `history.summary` and to no other round. The cache clock holds one order per round (`schedule_id` = uuid5 of the policy's namespace and `cache:<rk>`), so a call of one round never re-arms another round's order. `state` `window_plans` maps each round key to the time of its last rebuild; every rebuild stamps its own round and deletes the state of the rounds idle for longer than `round_plan_idle_s` (default 2592000 s, 30 days), then of the oldest beyond `max_round_plans` (default 64) -- never its own; what a dropped round owns falls with its plan (GH #949): its state rows including `summary_audience:<rk>` and its summary slot, deleted only after the registry write that drops it was won, row by row against the value read. The first call of a returning round whose newest visible summary is its own lays its leaf, slot and binding afresh from that `summaries` row; a cache order of the round that is still armed falls too -- the timer is told `remove` for the round's id (it marks the row and keeps it), an order that struck already gets none, and a strike before the removal finds no `last_call:<rk>`. A handover leaf bound to no audience reaches no round and falls at the next rebuild of any round. The ledger declares `state.key` unique (`state_key`), so the first write of a round's key is an insert only one writer wins, and a lost registry write is read and put again (at most three times). The bare keys of the one plan per hive (`window_plan`, `rebuild_running`, `last_call`, `armed_call`, `actions_pending`, `pending:summary`, `summary_audience`, a bare `history.summary` slot) are neither read nor moved: every round starts its plan afresh. `round_key`, `round_canon`, `own_slots` and `prune_plans` are pure functions like those below.

**Reading the round (`in_read`, GH #949).** An installed app reads the ledger of its round on `in_read`, answered on `read` with `hop.read_tag` echoed: `what` `turns` pages the wall rows its round may see (oldest first from the cursor `since`, `limit` 20 by default and 100 at most, `next` empty at the end, within a tenth of the reader's window, `hop.input_soft` of the read -- never the window this hive serves, which is another model's -- every row whole when the read names none; a first row larger than that is cut with the mark of the window rule below and flagged `cut`), `sessions` lists the sessions with their last time. The round is `context.audience_set` and nothing else, matched through `covers` like every reader of the ledger: a read without a round, or with `[]`, is answered `missing_audience` and reads nothing, a row reaches the read only when its audience holds the round, and a failed store read is `store_error`, never an empty page. The way in is `install_app` `reads`, which names the app's cell and the brain by `hop.organ`; a run the timer wakes carries no round and is refused.

**The price of the window (GH #1038).** A model's limits differ per model, and a cached window is not free: at a cached price of 10 % of the input price, a 500k window costs on every turn what 50k fresh tokens cost. The llm cell stamps the answering model's catalogue values on every answer (GH #1037): `input_soft` and `input_hard` in tokens, `cost_in` and `cost_cached_in` in cents per million tokens. With `input_soft` on the tap they replace the role's own numbers -- `compress_at` of the model's window orders nothing: a rebuild is due at `input_soft` (`curate_mark` `soft`), over `input_hard` (`hard`; the llm cell refuses such a call itself), and under soft when keeping the cached rest costs more over `amortise_turns` turns than one rebuild, `(window - aim) * cost_cached_in * N > aim * cost_in` (`cost`). The aim of a `soft` or `hard` rebuild is `input_soft` times `rebuild_to` / `compress_at` (the share of the window W11 made soft keeps its proportion), `input_soft` itself for a `hard` rebuild of a role without one; a `cost` rebuild aims lower, at `input_soft` times `rebuild_to` -- with the soft share as its aim the rule would need a cached price above 23 % (talky) of the input price and never fire, with this one it is due under soft from 0.7 (talky, consult) or 0.5 (coding, research) of `input_soft` at a cached price of 10 % and ten turns. The rule is conservative: it counts the rebuild at `cost_in` in full, neither the cached part the rebuilt call itself still reads nor a provider's cache-write price (`cost_cache_write`). Worked example: `cost_in` 10 cents per million, cached 10 % of it, a 500k window rebuilt to 100k -- keeping it costs 0.4 cents a turn more, the rebuild 1 cent once, so it pays back on the third turn. Every turn keeps `{call, curate_mark, window_tokens, cached_tokens, cost_cents, input_soft, input_hard}` under `state` `curate:<rk>`, and a turn with the package's values writes the same as a `marks` row of kind `curate`; the clock order of such a rebuild carries the mark as its `reason` and as `curate_mark`. The window is measured, never summed: after a `length` continuation the llm cell reports `tokens_prompt` as the sum of every call of the answer, so the package's rule takes the smaller of that and the policy's own projection of the call (every system leaf and every message, kept as `state` `window_est:<call>` until the tap -- a call no tap answers loses it to the next call of its round, and the round's pointer `est_call:<rk>` falls with the round --, estimated like the llm cell estimates a request: UTF-8 bytes of every string and key / 3, an inline image 1024 tokens). And because the cell refuses over `input_hard` on that estimate, `hard` is also due when the estimate of the next window -- this call plus its answer -- reaches 0.9 of `input_hard`; the tenth is headroom for what the projection does not see (the provider request's framing, the next turn, a tool result). Without `input_soft` (an old package) the rule of before holds and the mark is `none`.

**The role's own lines (GH #1272).** A conversation's window reached the model's soft line practically never (luna 250000), so a role's `tiers`, `keep_rounds` and day horizon never applied and whole days lay raw in the window. Two more marks order a rebuild under soft, package or not: `target` when the window reaches the role's `window_target` (tokens; talky 40000, quick 12000, 0 = off, every instance may set its own), and `day` for a role with `horizon` `day` when the turn is on another UTC day than the newest round of the round's last rebuild (`state` `last_rebuild_day:<rk>`, written by every rebuild of such a role; a round that never rebuilt starts at the day of its first answer). The turn's day is its own time where `./intake` stamped one (a replay channel's `happened_at`, the clock the rows age by), the tap's clock otherwise. Both aim at `window_target` times `rebuild_to` / `compress_at`, never above a soft rebuild's aim (`day` of a role without a target at the soft aim). A `target` rebuild that leaves the window over the target (the rounds kept raw alone are that large) is not repeated on every turn: the round keeps the window of its last `target` order (`state` `target_at:<rk>`), lowered on every later turn to that turn's window when it is smaller, so the row holds the window the rebuild left; the next `target` waits until the window has grown by `window_target` minus the aim from there, or has fallen under the target; until then the mark is `none` and the turn's `curate` stamp says `target_hold`. The order is `hard`, `soft`, `day`, `target`, `cost`. A `day` rebuild keeps raw only the `keep_recent` rounds of the running day, so the day before takes its tier form (talky: the summary) -- its tool results included -- and today stays raw.

**A refused read (GH #1225).** A ledger leg the store refused is never read as an empty answer. A call's window reads once more (the reason carries `reread:`; the normal path takes no extra hop); a second refusal sends the call with its system part and its round, without what is missing, and says so: one `cuts` entry per missing part (`what` `wall`, `slots` or `pins`, `shown` 0, `error_code`, `legs`) and one `store_error` mark. A hash read refused twice (`b-wallh`, `b-keeph`, `b-slotsh`, `b-pins`, the parked turn `b-slimq`, or the cover `b-cover` of a call whose plan holds none) is the same cut of the part it was read for, never a `missing_block` for a block that stands. When `./intake` could not read a turn's plan or cover, the parked turn names those reads (`wall_unread`, `a-plan`/`a-cover`): the call shows its own turn only -- no older row, no `missing_block` -- with one `cuts` entry `{what: wall, error_code: store_error, legs: <the reads>}`; the `store_error` mark is `./intake`'s. With its slots unknown a call sends no system diff and stamps no `system_hash_sent`; a parked turn out of reach twice leaves no call, only the mark and a line on stderr. A rebuild step stops with the mark: a refused probe starts no rebuild, a refused claim is no lost race, a refused question or answer read frees the claim by its token. A refused tap read writes nothing it would derive from the answer's usage, only the round's last call and the mark. Every state row, block and model pin is written in one step (`insert` with `replace` on the key, `if_absent` on the hash, or on hash, source and audience for a pin), so a refused write never loses the row it replaces; a refused window-form write empties the child's form cache, and the next call puts every form again.

## The ways of a call (`path_routes`, GH #1247)

The route cell of the composite stamps every turn (`talk`, `simple`, `complex`, `research`); the collector carries the path on the seam as `hop.path` and the parent's edge lifts it into `context.path`. The stamp recommends, `./policy` decides (R-WP-1): `path_routes` names the way the call leaves on. `quick` is the short window of the role `quick` with the class's tools (`quick_tools`) callable and the stamp's other families as hints (R-WM-1: the curator owns what the model sees); `consult` and `research` are one mechanism (R-WP-9): the whole errand leaves for the backend under its own `consult_id`, without a call of the voice model (R-WP-5), and the session's speaking calls carry `system.consult.pending` until the round that answers it -- recognised by `consult_id` on its context -- leaves on `brain` and takes the leaf down. The state row `consult_pending:<session>` holds the open consult; its `until` is the errand's stamp plus `consult_pending_ms`, for `research` plus `research_wait_ms` as well (GH #1260: the result comes in a later turn, after the wait the bridge names). **While it stands, no speaking call can start a second consult (GH #1280).** Every `brain` and `quick` call of the session denies the consult tool `consult_cogny` in its `tool_scope` (added to the channel's own `deny`; a scope whose `allow` does not hold the tool stays as it is), and the pending note stays beside it as information: told only in the note not to consult again, the brain of a `talk` turn consulted again anyway, as a tool call without a word beside it (production log of 2026-10-20: a second consult 9 s after the first, about 0.09 $). A consult the brain starts itself sets the same mark: `./intake` takes the ids of the `consult_cogny` calls in the model's output into the tap (`consults`, the folded form `consult{op: "cogny"}` too), and `./policy` writes the mark in its phase `tap` under the consult id the dispatcher stamps -- a follow-up's `consult_id` argument, else the call's id; cogny's advice comes back under it -- only while none stands, so a consult the curator sent keeps its own. With the `consult` family folded (`context.tools_folded`) the menu entry is `consult`, and the deny names it as well. The advice ends the mark and gives the tool back; an ask back of the backend (`consult_class` `ask`) does not, the consult still runs. `consult_pending_ms` is only the backstop for an advice that never comes.

**The speaker after a tool result (T4-10, GH #1248).** A quick round that called a tool comes back on the seam with the result (`iter` >= 1), and `./policy` names the speaker again: the quick voice keeps it only while the result is speakable as it is -- every tool call of the turn has its result (no open gap), the newest result is neither empty nor an error object (`error`/`error_code`), and the round is at most `quick_max_iter` iterations past its first call. Anything else leaves on `brain` with ONE `escalate` mark (`{call, path, from: quick, to: brain, reason, iter}`, reason `iterations`, `gap` or `unspeakable`), and the state row `escalated:<session>` keeps the turn with the brain for the rest of its round. The brain's call is the whole window: the quick way cleared `system_hash_sent`, so its tree goes whole.

**The bridge (T4-12, GH #1248).** A `consult` or `research` errand never leaves the person in silence (R-WP-4, R-TR-27): beside it `./policy` sends the quick voice ONE call with the leaf `instructions.bridge` -- an instruction, never a fixed sentence; the model says it in its own words (R-WP-4 a). On both ways the instruction tells the voice that it is handling the request for the person right now, in its own voice, and that it never refuses the request or says it cannot do something (GH #1258): told only that a backend was working, it once denied in its own name the very request the backend was answering. For `complex` (way `consult`) it says one short bridge sentence and the answer follows in the same turn within about `bridge_wait_ms` (R-WP-9); for `research` it names the waiting time (`research_wait_ms`) and keeps the conversation going, and the result comes in a later turn as a round with `consult_id` that leaves on `brain`. The bridge calls no tool and carries no consult id; the errand carries its mark as `hop.consult_wait_ms` -- read by no cell, a mark for whoever reads the message log -- and the state row `consult_pending:<session>` keeps it as `wait_ms`. The bridge is a model call of its own with its own `calls` row (`trigger` `bridge`, GH #1260), so its tap books its usage. **The tool round has a bridge too (GH #1260, OR-WG-6).** A `simple` turn whose stamp needs a `tool` sends its quick call with `tool_scope.require` -- in the wave's lab the fast model called its tool in 0 of 5 turns and 7 of 10 probe calls, 10 of 10 only when the call was required, and then said nothing beside it -- so the bridge (`hop.bridge` `tool`) says the sentence the person hears while the lookup runs, told not to answer yet. It carries `hop.interim` `1`, which talky lifts into the context of the quick call and the dispatcher puts on its sentence: an interim answer leaves the round open for the tool result, a final one would end it at the fan-in. The bridge leaves BEFORE the required call, on the same edge: both go to the one `./quick`, a stateful `llm` cell that takes its mailbox one call at a time (`max_concurrency` is a knob of stateless cells), so the two cannot run side by side, and in this order the person hears the bridge after one model call, not two. **A tool round without its call goes to the brain (GH #1260, OR-WG-9).** The required call carries `hop.interim` `tool`. When its answer comes back without a tool call -- prose, an error such as the HTTP 404 of a host that refuses a forced call, or a cut -- the dispatcher does not say it, `./intake` keeps its prose out of the wall, and `./policy` (`tap`) takes the round on as the call `<call>-esc` on `brain`, from the copy of the parked turn `win` kept (`pending:<call>-esc`, dropped when the call came), with ONE `escalate` mark, reason `no_tool_call`, which names how the call ended (`finish`) and its `error` code; `escalated:<session>` keeps the turn with the brain. talky's `./quick -> ./errors` edge does not take the error of such a call (`context.interim` `tool`): the person hears the brain's answer, not an error report beside it. talky's `./curator -> ./brain` edge sets `context.interim` empty, so the brain's answer is the turn's final one. Every bridge states no content: its instruction forbids facts, numbers, results and guesses (a lab bridge stated a rain forecast before any lookup); the tool round's says only that it is looking it up, the consult's that the answer is still coming, and research names its wait. The tool round's bridge also names the lookup that runs beside it: the tools its `tool_scope` allows at the ops stage (not the hint stage), a family once, in words: where each looks ("on the web and at the weather service"; a family without words for its place is never named by its tool name -- beside named ones it adds "in other places", alone the sentence names no place), and it is told to write no tool call, JSON, code or command -- told the `code` name of its tool, the fast model wrote the call out as text and made weather up beside it in a probe. And every bridge is told never to speak of missing access, missing abilities or limits and to ask nothing about the request itself (GH #1260, OR-WG-13): a lab bridge, not knowing a tool worked for it, said it had no access to weather data and asked which day, while the `weather` call ran. The tool round's one sentence asks the person nothing at all, the consult's asks nothing about the request itself, and research keeps the conversation going while it waits (R-TR-27) -- on another subject, never on the request: told only that anything else was fine, it asked in a probe what mattered to the person in the request. Its window carries no `tool_call` or `tool_result` of earlier turns; on a consult and on a tool round it is the person's turn alone -- every text of the person since the last message that is not theirs, so a request sent in two messages stays whole, and never a pin standing as a message (`broadcast_mode` tail), which the window can put behind the turn (research keeps the quick window): an earlier answer in the window is a pattern the fast model follows -- in a probe it answered a consult in the bridge itself and said tonight's degrees on a tool round, and with the person's turn alone it did neither. The curator does not see the menu of the quick model: when the channel's scope names tools that menu does not carry, the `llm` cell drops the requirement (its `WARN` line), and the answer of that round comes without its sidecar block, after the bridge's interim sentence.

**Push candidates on a quick way (T4-08).** A candidate came into the window on the ask path of `./push` only, ahead of the round because the round waited for the memory. A routed round (`hop.path`, first assembly) does not wait for it, so `./intake` asks in its first read whether a live candidate stands; if one does and nothing of the turn is in the wall yet, the round stays parked, `./intake` hands `./push` a `push_round` (the round's words, `resume` = its parked key), and `./push` picks with its own rules and answers on `in_addendum` with `resume` -- always, an empty pair included -- without a question to the memory. `./intake` writes the pair and reads the round back behind it, so the pair opens the round. The quick window keeps a candidate pair (`call_candidates_*`) although it drops the memory's rows.

**The window rule (R-IG-1, GH #1085, since 1.11.2).** This hive is the one place that cuts what its model reads, and it cuts by shares of the usable window -- the catalog's `input_soft` the llm cell stamps on every answer, cut to the model's own window alone and kept in state `input_soft` -- turned into characters at 3 per token, never by a typed number: an earlier answer's sidecar block and the collector's sidecar contract (`instructions.sidecar`) 10 %, the summarizer's transcript and the handover note's transcript 50 % of the window of the model that reads them, the summarizer's (state `summarizer_input_soft`: the stamp on each of its answers, the bound of a refusal over its window -- a refused note is measured anew once --, before either `input_soft_fallback`), never the served one, the handover block 50 % (and always under the leaf bound of the llm cell's system gate: without a window the 4 MiB carrier ceiling, with one what the window takes at all), the push candidates' part 5 %, a `history_read` 10 % (a larger block by its id is read in pages, a larger turn range refused with `too_large` and its size), a page of `./reader` 10 % of the asker's window. Without a known window everything goes whole; a find said aloud (`fact`) always does, because the voice model that hears it is not the model this hive serves. The summary has no length of its own: the summarizer is asked to keep it as short as useful and as long as needed, and only a summary whose leaf would not fit the carrier (4 MiB, `CARRIER_MAX_BYTES`) is refused (`too_long: <n> > 4194304 bytes`). Over its share a text carries `...[cut: <shown> of <total> chars shown; <hint>]`, a section or block left out `...[dropped: <name> (<n> chars) over budget]` where it stood -- optional contract sections fall from the back, a required one never, and the contract's frame is written anew over the sections kept, so it never asks for a dropped one -- and every cut is also on the message's hop as `cuts` (`{what, shown, total, unit}`). A shortened block names its whole length (`[#<id>] <first line> [shortened, <shown> of <total> chars — history_read("#<id>")]`). Every ask of a producer (`recall`) carries `input_soft` (tokens, absent when unknown) beside `recall_input_soft`; the parent's edges lift only `recall_input_soft` into the context, so the alias is what the memory hive reads. A pin is refused only over the carrier, one system leaf of at most 4 MiB (`too_long: <n> > 4194304 bytes`); a smaller window's own bound refuses it at the llm cell, with its number. The candidates are switched by `push` `candidate_push` ("1", "0" off).

Numeric knobs take numeric strings; `null` or empty means the default. The word-for-word check (GH #1079) has no knob here: its rule rides on the section's hop, set by the parent's splitter knob `sidecar_verify` (`templates/talky/README.md`).

**A quote at its source (GH #1225).** Beside `turn`, `turn+recall` and `answer`, a field's rule may be `source` (`{"memory":{"items":"facts","quote":"source"}}`; the splitter hands the answer along as `verify_answer` for every rule that names `source`): the item names where its words come from -- `source` `person`, `peer:<ref>` (a bare `<ref>` too) or `agent:<name>`, trimmed and case-folded -- and the quote counts only in the rows of exactly that source: `person` the `user` rows of the turn and of the person's episode the turn answers (`episode_turn_id`: a round of advice or of a timer answers the person's row of its turn); `peer:<ref>` the `peer` rows of that speaker (`speaker_ref`) in the same two places; `agent:cogny` the turn's advice rows, `agent:voice` its delegations, `agent:app:<id>` and `agent:timer:<id>` its rows framed `[app <id>]` / `[timer <id>]` (the frame counts only with an `<id>` in the form of a name, `a-z0-9_.-`, at most 64 characters -- a text that merely starts with `[timer ]` stays the person's; the frame is the sender's, no shipped template sets one yet); `agent:self` the answer (`verify_answer`) and the final answers of the episode. So a round without a person row of its own -- the reasoning core's advice, a delegation, a round an app or a timer opened -- still checks a quote of the person. An item without a source is refused as `source_missing`, one in a form the check does not know as `source_unknown`, a quote not in the rows of exactly its source as `quote_not_in_source`, a failed read of those rows as `store_error`; every refusal leaves a `verify_reject` mark beside its `reject`, and a `topic` mark carries the topic's source. An item is never re-filed under another source. A round an app or a timer opens enters as a user turn whose text starts with its frame (`[app <id>] ...`, `[timer <id>] ...`, id lower-case letters, digits and `_.-`, at most 64); its wall row is kind `app`/`timer`, never `user`, so it never becomes the person's episode.

A model pin carries the intersection of its `pin` mark and every wall row of its block, NULL when any is. A refusal is an answer under the same call id, its code in the text (`error`) and in `hop.error_code`: `bad_arguments`, `bad_pattern`, `bad_range` (`since` after `until`, a turn range that runs backwards, an `offset` past the end of the block's text), `not_found` (an id or a turn this wall never carried), `ambiguous` (an id prefix that names two blocks; `candidates` lists them), `too_large` (`size`, `budget`; a block by its id only where paging cannot reach it -- not one character of it fits the budget, or it has no text; a range with more rows the round may see than `scan_budget` `block_count_at_least`, one whose raw text is over ten budgets `raw_size`, both refused before a body is read), `unknown_tool`, `ledger_error`, `missing_audience` (the call's context declares no `audience_set`; nothing is read). The model's own `history_*` calls and their answers are on the wall like every round, but no hits, no neighbours and no blocks of a range; by its id each is read whole. A read of a block TRIM released writes one `marks` row `reread` (the block's hash, the reading turn), once per block and turn; released is what the newest `scan_budget` `release` and `pin` marks of the block the round may see leave in `seq` order (GH #931).

**The row bound (GH #925, OR-BD-86).** Rows the round may not see count toward no budget, no page and no neighbour window, but every read stops at twice `scan_budget` rows in all. Where that leaves the answer open -- the visible rows it reached do not settle what the call answers on the same wall without the others -- the call answers in the cut form and shows nothing it read: a search `hits` [], `truncated_scan` true, `stopped_at_limit` false, `cut_by` `scan_budget` and a `detail`, no `scanned` and no `total_hits`; a `history_read` -- a turn range, or a read whose blocks' `release`/`pin` marks reach the bound -- `too_large` with a `detail` and `budget`, no `block_count_at_least`; an outline `sessions` [], `truncated_scan` true and a `detail`. The form is the same on every wall that reaches the bound, so hidden rows move one bit per call -- the bound was reached -- and never a count. It takes at least `scan_budget` hidden rows among the first twice `scan_budget` + 1 rows one read meets (of the `release`/`pin` marks of a read's blocks, more than `scan_budget` among their newest twice `scan_budget`); for the neighbours of a search with `context` (a side whose `context` + 4 nearest rows hold a hidden one is read again, one ledger round trip, the short sides sharing twice `scan_budget` rows) at least `scan_budget` / hits - `context` - 3 hidden rows of the hit's session on one side -- at the defaults with `context` 2: 245 with 20 hits, 620 with 8. Below that no answer shows a hidden row, its id or a word of it, and every number an answer carries counts rows the round may see, never all rows (`scanned`, `total_hits`, `block_count_at_least`, `size`, `turns`, `omitted_sessions`). Metadata channels (GH #932): since 1.4.0 every reader asks the ledger for the rows the round may see (`where audience_set covers <round>`; a round-less read asks for `[]` and `["*"]` rows of its own session), so a hidden row is never read -- page ends, `scanned`, the push and renewal windows and the per-turn `turn_index` hang on visible rows alone, and the row bound and its cut form are a second line that no longer fires on hidden rows. What stays: how long a read takes (the store still walks the hidden rows), the freshness check of a new session's handover, and the counts of `./stats` (OR-BD-6); where a rebuild cuts the window is no longer among them, the plan being one per round since GH #943 (a `release`/`pin` mark acts only on the windows of rounds that may see it and survives every rebuild of another round). `hop.turn_id` of `turn_write` is `<session_id>#<tag>-<index>`, `tag` the first 8 hex of the SHA-256 of the canonical round, the index counted per session and round. The round pays with that call's answer: a narrower `since`/`until` brings it back (a search also a smaller `limit` or no `context`, a range fewer turns, an outline a later `since`).
