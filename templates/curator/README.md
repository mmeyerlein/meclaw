# `curator@1.11.3`

The window of one model, owned in one place, with a ledger of every call. Contract tables only; the prose follows with the program it belongs to.

Since 1.1.0 ([#892](https://github.com/mmeyerlein/meclaw/issues/892), [#893](https://github.com/mmeyerlein/meclaw/issues/893), [#895](https://github.com/mmeyerlein/meclaw/issues/895), [#896](https://github.com/mmeyerlein/meclaw/issues/896)) the window follows a role (`role`: `talky`,
`consult`, `coding`, `research`), foreign words and tool results stand behind a short id
`[#<12 hex>]` the model can release or pin through the `window` section of its answer, another hive
can pin a text into the window (`in_pin`), and the hive answers the collector's menu question itself
(`./schemas`). Three cells joined it: `./history` answers the `history_*` tools out of the ledger,
`./push` builds the memory leg's question and looks a `gap` up after the answer, and `./handover`
hands a new session a note on the last one and a renewed duplex call a block of the recent
conversation. Lanes joined the boundary, so it is the second digit.

Since 1.1.1 ([#904](https://github.com/mmeyerlein/meclaw/issues/904)) the cache clock is one standing order under a fixed id per hive (per round since GH #943),
re-armed on every call (`add` with `rearm`), so the timer keeps one row for it instead of one
per call. No lane moved; a promise is repaired, so it is the third digit.

## Lanes (into the hive path, on `hop.route`)

| Lane | From | Carries |
|---|---|---|
| `in_curate` | the context collector | `messages[]` the whole running round (opening turn, evidence pairs, every tool iteration so far), never history; `system` the per-round slots; `tool_scope` if set; `hop.session_id`, `hop.turn_id`, `hop.iter` and whatever else the caller puts on the call (no session = `default`, no turn = a round of its own). An `assistant` text in a round without a tool call of its own (a duplex turn pair; the evidence pairs `memory_recall` and `affinity_brief` do not count) is a final answer and an episode. Answered by one `brain`. |
| `in_slots` | the context collector | `system` only (tool menu, sidecar contract). Kept as the collector's slots, sent with the next call whose system changed; no call of its own. |
| `in_llm` | the tap: every output of the model | the raw output with `hop.finish_reason`, `hop.model`, `hop.tokens_*`, `hop.cost`, `hop.cache_expires_at`, `hop.context_window`, the answering model's limits and prices `hop.input_soft`, `hop.input_hard`, `hop.cost_in`, `hop.cost_cached_in` (GH #1038, absent from an old package), and `context.curator_call`, `context.session_id`, `context.turn_id`, `context.iter`. A final answer (`stop`, `length`) enters the wall from here; the sentence beside a tool call (`tool_calls`) enters as an interim answer, not final, never an episode. Without a session it is session `default`, without a turn the round of its call (the rule of `brain`); without `context.curator_call` it is dropped and said on stderr. |
| `in_pack` | an identity pusher | `system.{identity,identity_short,persona,handover,instructions}` (or `slot` + `content`); the context rides on to `pack_ack` untouched. |
| `in_close` | the session keeper | `context.session_id` of the closed session; `context.audience_set` the round its generation was opened in, the only round the `write` batch is gated by. |
| `in_model` | the llm-registry | a params-only body for `./summarizer`, only when `hop.subscriber` names it (the one model door of the hive). |
| `in_section` | the parent's splitter | one section of the sidecar block of an answer of the model (`hop.section`, body `{messages: [], section, payload}`, the answer's context). `window` (`release`/`pin`: block ids) becomes `marks` rows; `gap` goes to `./push` (through `./policy`), which marks it once and looks it up after the answer; `memory` a `topic` mark (`{movement, name}`, movement start/continue/end) and, when `./intake` `pass_sections` names it, leaves again unchanged on `sidecar`. Any other section is dropped and said. A section whose hop carries `sidecar_verify` -- the parent splitter's rule for it, canonical JSON, GH #1079 -- and is none of `window`, `gap`, `things` is checked first and leaves on `sidecar` whatever its name: every item of its array (the rule's `items`, else the first list), each named field word for word against the round's `user`/`peer` turns (`turn`), those and the round's memory bundle (`turn+recall`) or the body's `verify_answer` (`answer`). Both sides casefolded, NFC, curly quotes and dashes folded, whitespace collapsed, punctuation at the edges stripped; the quote stands in one source at word boundaries, under three words only as a whole source; no fuzzy match. A `memory` section is checked only where `pass_sections` hands it on. |
| `in_pin` | another hive | `pins[]`, each `{text, source, until?}`: `source` one path segment, never `model`; `until` RFC 3339. Optional `replace_sources[]` (at most 16, each by the `source` rule): every live pin of those sources ends first (`until` = now, no row deleted), except a hash the new set carries; `pins: []` with it empties those sources. A block of kind `pin` and a `pins` row; the window shows it under `system.pinned.<source>.<id>`. Nothing else of the hive is written through this door. A pin without `context.audience_set` is refused (`missing_audience`, stderr, nothing written). A pin may name its own `audience_set` (GH #972, see below). |
| `in_schemas` | the collector's menu question | `tools[]` the declared names. `./schemas` answers on `tool_schemas` with the curator's tools and sections (`CURATOR_OFFER`). |
| `in_history_call` | the parent's dispatcher, on `hop.tool_name` starting `history_` | one `history_search`, `history_read` or `history_outline` call (GH #893): one `tool_call` turn, the arguments as its text, `hop.tool_call_id`, `hop.tool_name`, the round's context. Answered by one `tool_result` out of this hive's ledger. |
| `in_recall_ask` | the context collector | its per-turn memory ask (route `recall`): `phase`, `turn_id`, `session_id`, `iter`, `recall_query`, `memory_tier`, `recall_window_from`, `recall_window_to`, the person's words as `messages[]`. Answered by exactly one `recall` (`./push`, through `./policy` for the knobs); never held back. |
| `in_gap_bundle` | the memory, through the parent's edge | the answer to a gap's own ask, recognised by `context.gap_ask`; never the collector's. A find becomes an addendum; an empty bundle, a reject or the empty-state sentence is nothing. |
| `in_renewed` | the member, from a duplex channel | a live session of a running call was renewed at its provider's limit (GH #896): `hop.call_id`, `hop.renewal_n`. Answered by one `sidecar` without a model. |
| `in_stats` | an observer, through the parent (GH #926) | a question, all hop: `stats_tag` (1 to 64 characters), `stats_from`/`stats_to` (RFC 3339, `from` counts, `to` does not, at most 31 days), `stats_kinds` (a JSON array as text out of `calls`, `gap`, `reread`, `ask`, `correction`, `tool_error`), `stats_samples` (0 to 50, default 0). Answered by exactly one `stats` out of this hive's ledger, read only. |

A gap's find enters the wall of the session's next round, ahead of its first turn, as a `memory_recall` pair whose result opens with `[addendum to your last answer -- looked up after it, for: <gap>]` -- `./push` hands the pair to `./intake`, the wall's one writer, on the internal lane `in_addendum`; its marks are `gap` (the signal), `addendum` (the find, kept) and `addendum_done` (shown, or why not). A find the window already carries is not shown twice, and one for a session that has ended stays unshown.

**Push candidates (`in_candidate`, GH #949).** Another hive -- an installed app, a store of the person's things -- hands the curator texts it wants in the model's window of a later turn: `{source, candidates: [{id, text, audience_set?, triggers?, until?, once?, priority?}], withdraw?: [id]}`. The round is `context.audience_set` of the push and is required (`missing_audience`, nothing written); a candidate without its own `audience_set` takes the round, one with it must stay within the round (every member in the round, `*` only when the round names `*`), else that candidate alone is refused `audience_widened` (a candidate naming `[]` widens every round but `[]` itself); one out of its bounds (at most 32 per body, `id` up to 64 characters, `text` at least 1 character -- no upper bound of its own (R-IG-1), up to 16 `triggers` of up to 64 characters and none of punctuation alone, `priority` 0 to 9, default 5) is refused `invalid_input`, and a repeated `id` counts by its last entry. A kept candidate is a block of kind `candidate` and one `candidates` row per `(source, id)`: a new text, `once` or trigger list starts it afresh, `withdraw` ends it (`until` = now), and one whose `until` has passed is kept and never shown. In its `ask` phase `./push` takes the candidates the round of the ask may see (`covers`, never wider; a round-less ask only `[]` and `*`) that are live, not a used `once`, and either carry no trigger or one the person's words of this turn name as whole consecutive words (NFC, case-folded, a possessive `'s` dropped) -- and not again within `candidate_cooldown` turns (default 5). Best first by `priority`, then the youngest, they reach the model as ONE `memory_recall` pair that `./push` hands `./intake` (`in_addendum`, the road of a gap's find) for the round of the ask, ahead of its first turn: the call (id `call_candidates_<16 hex>`) asks for the triggers the person's words hit, joined with ", " (empty when none carried one), and the result is the line `[addendum -- notes handed to this conversation for this round; not said by the person]` with the part `[<text>; <text>]` below it, whole candidates within a twentieth of the window this hive serves (every picked one without a known window), the ones left out said behind the part as `...[dropped: <n> candidates (<m> chars) over budget]` and kept for a later turn (`candidate_push` "0" = off); the memory question (`recall_query`) never carries them, so every turn asks exactly as before. `once` is true by default without triggers and false with them, and a shown `once` candidate is used. A receipt `candidate_ack` `{source, stored, refused: [{id, error_code}]}` leaves only when the push carries `hop.ack` "1": a generation fans one push out to the curator of each of its brains, and receipts nobody asked for would be dead letters. The way back out is the sidecar section `things`, offered only when `things_section` is "1" at `./schemas` and at `./intake` (the instruction is `things_instruction`): at most 8 `{name, kind?, note?}` under `items`, checked by `./intake` and handed on as ONE `thing_seen` `{items, turn_id, episode_turn_id?, session_id}` with the round in `context.audience_set` -- never without a round, and never as `sidecar` as well, because the parent's splitter hands `things` to the curator like `window`, `gap` and `memory`.

The model behind the hive orders its system part with `history` after `identity`, `persona` and `instructions` (`system_order`): the summary changes only on a rebuild and stands last. A brain `llm` with `system_writable` behind a curator must allow `history`, `pinned`, `roster`, `consult` and `instructions` -- every call carries them as `$replace` roots.

**The handover (`./handover`, GH #896).** A closed session (`in_close`) leaves a note: its turns go through `./summarizer`, off the hot path, and the answer is kept as a block of kind `summary` with a `marks` row `handover` (state `prepared`); a session that left no turn leaves nothing. The first call of a session this window did not serve last goes from `./policy` through `./handover` once, without a model: a NEW session (no wall row before this round) gets the leaf `history.handover` -- the note of the session served last, when it closed, and the topic still open, each only when the new session's round passes its audience (`state` `handover_audience` keeps the leaf's audience bound to the leaf's hash, and the window shows the leaf only when that hash is the slot's and the round passes the audience) (the `name` of the newest `topic` mark that names one, unless an `end` came after it) -- and the call returns to `./policy` (`handover-done`), which reads its window as for any call: the plan's cover, the rows it holds, every pin. The leaf carries no pins, because the window shows every valid pin already. It stands for the session and falls at the first rebuild after it of the round its audience names (GH #943). A renewed live session (`in_renewed`) sees no system part of this hive, so its block carries it all: the newest `renew_rounds` rounds as text, the summary, the pins, the open commitments (pins with `source` `commitment`) and the topic, at once and without a model. Open commitments stay empty until a hive pins them through `in_pin`; no parent draws that door yet. Every block is at most its share of the window (the window rule below), cut by rank: pins and commitments, then the topic, then the turns, the summary last. The pack family `handover` is the identity pusher's and is never touched; this leaf is `history.handover`, owner `curator`.

## The window per role

`./policy` `role` picks the presets; every knob set on the instance wins. The window is the system part (slots, `pinned.*`, stubs) + the wall after the plan's cover, each block as the plan shows it + the running round. A rebuild (cold cache, a line of the model's package -- below --, or without a package `tokens_prompt` over `compress_at` of the model's own window) makes the plan: segments by `horizon`, their form by `tiers` (`raw`, `summary`, `none`), the newest `keep_recent` rounds and the newest round always raw, the model's pins raw. Over `rebuild_to` of the usable window it shrinks old tool results (outside `keep_rounds`), then stubs tools unused for `stub_tools_after` rounds, then gives the summary up. Between two rebuilds only the end of the window moves.

| Knob | none | `talky` | `consult` | `coding` | `research` |
|---|---|---|---|---|---|
| `compress_at` / `rebuild_to` | 0.5 / 0 | 0.5 / 0.35 | 0.5 / 0.35 | 0.4 / 0.25 | 0.4 / 0.25 |
| `keep_recent` | 12 | 40 | 10 | 20 | 10 |
| `horizon` | `all` | `day` | `task` | `task` | `task` |
| `tiers` | raw,summary | raw,summary,none | raw,summary | raw,summary | raw,none |
| `keep_rounds` / `stub_tools_after` | 0 / 0 | 2 / 20 | 2 / 10 | 3 / 20 | 1 / 10 |
| `broadcast_mode` | tail | tail | tail | tail | tail |
| `recall_push` / `recall_budget` | off / 0 | "1" / 200 | off / 0 | off / 0 | off / 0 |
| `short_ids` | off | "1" | "1" | "1" | "1" |
| `identity_budget` | full | full | full | full | full |

**No window of a role's own (R-IG-1, GH #1085, since 1.11.3).** The usable window is the catalog row of the answering model: `input_soft`, which the llm cell stamps on every answer (GH #1037), cut only to the model's own reported window. Until 1.11.2 a role capped it (`quality_cap`: talky 120000, consult 80000, coding 70000, research 80000 tokens, GH #892) -- a talky under luna (`input_soft` 250000) kept 120000, handed that to every producer and, on an answer without the row's limits, rebuilt at 60000. Whether a model reads a smaller window well is a question of its catalog row, never a knob of this hive.

**Short ids.** With `short_ids` on, somebody else's words and a tool result begin with `[#<12 hex>] `, the first 12 hex digits of the wall block's hash; the model's own answers and tool calls never do. The model names ids in its `window` section: `release` shows the block as `[#<id> released — history_read("#<id>")]` from the next rebuild on, `pin` keeps it raw below the cover. Identity, persona, instructions and the round the section was said in stay; an unknown id is ignored and said. A block with `valid_until` passed at the plan's time shows as `[#<id> expired]`. The ledger keeps every block byte for byte; a form the window shows is a block of kind `view`.

**Window plan per round (GH #943).** `./policy` keeps one window plan per round, not one per hive: with one plan, a rebuild one round started set the cut, the shrunk results and the stubs of every other round's window. A round's key `round_key` is the first 12 hex digits of the SHA-256 of the canonical round (the JSON array sorted, without duplicates, as `audience_set` carries it); a call without a round has the key of `[]`, and `["*"]` is a round of its own. Under it `state` holds `window_plan:<rk>`, the rebuild claim `rebuild_running:<rk>` (one rebuild per round at a time), `last_call:<rk>`, `armed_call:<rk>`, `actions_pending:<rk>`, `pending:summary:<rk>` and `summary_audience:<rk>`, and `./intake` hands a call on with the plan of its own round. The summary slot is `history.summary:<rk>`, shown to its round as the leaf `history.summary` and to no other round. The cache clock holds one order per round (`schedule_id` = uuid5 of the policy's namespace and `cache:<rk>`), so a call of one round never re-arms another round's order. `state` `window_plans` maps each round key to the time of its last rebuild; every rebuild stamps its own round and deletes the state of the rounds idle for longer than `round_plan_idle_s` (default 2592000 s, 30 days), then of the oldest beyond `max_round_plans` (default 64) -- never its own; what a dropped round owns falls with its plan (GH #949): its state rows including `summary_audience:<rk>` and its summary slot, deleted only after the registry write that drops it was won, row by row against the value read. The first call of a returning round whose newest visible summary is its own lays its leaf, slot and binding afresh from that `summaries` row; a cache order of the round that is still armed falls too -- the timer is told `remove` for the round's id (it marks the row and keeps it), an order that struck already gets none, and a strike before the removal finds no `last_call:<rk>`. A handover leaf bound to no audience reaches no round and falls at the next rebuild of any round. The ledger declares `state.key` unique (`state_key`), so the first write of a round's key is an insert only one writer wins, and a lost registry write is read and put again (at most three times). The bare keys of the one plan per hive (`window_plan`, `rebuild_running`, `last_call`, `armed_call`, `actions_pending`, `pending:summary`, `summary_audience`, a bare `history.summary` slot) are neither read nor moved: every round starts its plan afresh. `round_key`, `round_canon`, `own_slots` and `prune_plans` are pure functions like those below.

**Reading the round (`in_read`, GH #949).** An installed app reads the ledger of its round on `in_read`, answered on `read` with `hop.read_tag` echoed: `what` `turns` pages the wall rows its round may see (oldest first from the cursor `since`, `limit` 20 by default and 100 at most, `next` empty at the end, within a tenth of the reader's window, `hop.input_soft` of the read -- never the window this hive serves, which is another model's -- every row whole when the read names none; a first row larger than that is cut with the mark of the window rule below and flagged `cut`), `sessions` lists the sessions with their last time. The round is `context.audience_set` and nothing else, matched through `covers` like every reader of the ledger: a read without a round, or with `[]`, is answered `missing_audience` and reads nothing, a row reaches the read only when its audience holds the round, and a failed store read is `store_error`, never an empty page. The way in is `install_app` `reads`, which names the app's cell and the brain by `hop.organ`; a run the timer wakes carries no round and is refused.

**The price of the window (GH #1038).** A model's limits differ per model, and a cached window is not free: at a cached price of 10 % of the input price, a 500k window costs on every turn what 50k fresh tokens cost. The llm cell stamps the answering model's catalogue values on every answer (GH #1037): `input_soft` and `input_hard` in tokens, `cost_in` and `cost_cached_in` in cents per million tokens. With `input_soft` on the tap they replace the role's own numbers -- `compress_at` of the model's window orders nothing: a rebuild is due at `input_soft` (`curate_mark` `soft`), over `input_hard` (`hard`; the llm cell refuses such a call itself), and under soft when keeping the cached rest costs more over `amortise_turns` turns than one rebuild, `(window - aim) * cost_cached_in * N > aim * cost_in` (`cost`). The aim of a `soft` or `hard` rebuild is `input_soft` times `rebuild_to` / `compress_at` (the share of the window W11 made soft keeps its proportion), `input_soft` itself for a `hard` rebuild of a role without one; a `cost` rebuild aims lower, at `input_soft` times `rebuild_to` -- with the soft share as its aim the rule would need a cached price above 23 % (talky) of the input price and never fire, with this one it is due under soft from 0.7 (talky, consult) or 0.5 (coding, research) of `input_soft` at a cached price of 10 % and ten turns. The rule is conservative: it counts the rebuild at `cost_in` in full, neither the cached part the rebuilt call itself still reads nor a provider's cache-write price (`cost_cache_write`). Worked example: `cost_in` 10 cents per million, cached 10 % of it, a 500k window rebuilt to 100k -- keeping it costs 0.4 cents a turn more, the rebuild 1 cent once, so it pays back on the third turn. Every turn keeps `{call, curate_mark, window_tokens, cached_tokens, cost_cents, input_soft, input_hard}` under `state` `curate:<rk>`, and a turn with the package's values writes the same as a `marks` row of kind `curate`; the clock order of such a rebuild carries the mark as its `reason` and as `curate_mark`. The window is measured, never summed: after a `length` continuation the llm cell reports `tokens_prompt` as the sum of every call of the answer, so the package's rule takes the smaller of that and the policy's own projection of the call (every system leaf and every message, kept as `state` `window_est:<call>` until the tap -- a call no tap answers loses it to the next call of its round, and the round's pointer `est_call:<rk>` falls with the round --, estimated like the llm cell estimates a request: UTF-8 bytes of every string and key / 3, an inline image 1024 tokens). And because the cell refuses over `input_hard` on that estimate, `hard` is also due when the estimate of the next window -- this call plus its answer -- reaches 0.9 of `input_hard`; the tenth is headroom for what the projection does not see (the provider request's framing, the next turn, a tool result). Without `input_soft` (an old package) the rule of before holds and the mark is `none`.

**The window rule (R-IG-1, GH #1085, since 1.11.2).** This hive is the one place that cuts what its model reads, and it cuts by shares of the usable window -- the catalog's `input_soft` the llm cell stamps on every answer, cut to the model's own window alone and kept in state `input_soft` -- turned into characters at 3 per token, never by a typed number: an earlier answer's sidecar block and the collector's sidecar contract (`instructions.sidecar`) 10 %, the summarizer's transcript and the handover note's transcript 50 % of the window of the model that reads them, the summarizer's (state `summarizer_input_soft`: the stamp on each of its answers, the bound of a refusal over its window -- a refused note is measured anew once --, before either `input_soft_fallback`), never the served one, the handover block 50 % (and always under the leaf bound of the llm cell's system gate: without a window the 4 MiB carrier ceiling, with one what the window takes at all), the push candidates' part 5 %, a `history_read` 10 % (a larger read is refused with `too_large` and its size, never shortened), a page of `./reader` 10 % of the asker's window. Without a known window everything goes whole; a find said aloud (`fact`) always does, because the voice model that hears it is not the model this hive serves. The summary has no length of its own: the summarizer is asked to keep it as short as useful and as long as needed, and only a summary whose leaf would not fit the carrier (4 MiB, `CARRIER_MAX_BYTES`) is refused (`too_long: <n> > 4194304 bytes`). Over its share a text carries `...[cut: <shown> of <total> chars shown; <hint>]`, a section or block left out `...[dropped: <name> (<n> chars) over budget]` where it stood -- optional contract sections fall from the back, a required one never, and the contract's frame is written anew over the sections kept, so it never asks for a dropped one -- and every cut is also on the message's hop as `cuts` (`{what, shown, total, unit}`). A shortened block names its whole length (`[#<id>] <first line> [shortened, <shown> of <total> chars — history_read("#<id>")]`). Every ask of a producer (`recall`) carries `input_soft` (tokens, absent when unknown) beside `recall_input_soft`; the parent's edges lift only `recall_input_soft` into the context, so the alias is what the memory hive reads. A pin is refused only over the carrier, one system leaf of at most 4 MiB (`too_long: <n> > 4194304 bytes`); a smaller window's own bound refuses it at the llm cell, with its number. The candidates are switched by `push` `candidate_push` ("1", "0" off).

Numeric knobs take numeric strings; `null` or empty means the default. The word-for-word check (GH #1079) has no knob here: its rule rides on the section's hop, set by the parent's splitter knob `sidecar_verify` (`templates/talky/README.md`).

**The round of a pin (GH #972).** `context.audience_set` of an `in_pin` message is the ceiling: for an app it is its member's round, stamped by the builder's pin edge after every edge of the app. A pin without its own `audience_set` takes the ceiling. A pin that names one keeps it when it is (a) the round of the turn this message belongs to -- `context.turn_round`, stamped once by the edge that raised the turn and never by a config's own edge (the mutation door and the boot pass refuse that as `edge_schema`), so no app can claim it -- or (b) inside the ceiling (narrower, or the ceiling itself). Anything else is not placed and not lost: a stderr line `pin:held source=<s> hash=<12 hex>: <reason>`, and the source pins it again in a turn of that round, whose own stamp is the proof -- nothing is placed out of the ledger. Fail-closed: a chain no turn raised (an app's own timer) has no `turn_round`, so only rounds inside the ceiling are kept; a group goal therefore shows in its group from the next turn of that group on. Since a pin carries its round, every audience group of one source travels in ONE message with ONE `replace_sources`: the replacement ends every live pin of the source in any round except the ones the message carries -- a held pin included, so a turn of another round does not end the group's pin. Two pins of one text in two rounds are one block and one row (the hash names the text): within one message the first is kept, across messages the later round wins.

**Who a row reaches (GH #925).** Every row of `wall`, `calls`, `marks`, `summaries` and `pins` carries `audience_set`, the canonical JSON array of the round that caused it (`context.audience_set`; a summary and a handover leaf the intersection of their sources and of the round they were made for -- a wider round that joins later does not see them, so whether they appear never hangs on a row it may not see --, a handover note the intersection of every row of its session, so a long session's note may come out narrower than its transcript, never wider; `*` neutral), or `[]` when that round declared none (PP-BD-12, since 1.4.0; NULL only in rows from before the rule, and those reach nobody). A reader -- the window, the handover, the history tools, the recall question, the close batch -- hands a row to a round only when the row's set names `*` or holds the round as a subset (the affinity rule); a NULL row reaches nobody. A round that declares no audience sees the rows of its own session that declare none either, or name `*` -- never a row a declared round said there -- and nothing else, and its call is marked `missing_audience` (a round-less recall question likewise takes no find of a declared gap); each round's clock order carries that round, so a rebuild summarises only what that round may see; a rebuild without a round keeps its plan without a summary (the window shortens, nothing is condensed). A model pin carries the intersection of its `pin` mark and every wall row of its block, NULL when any is. The close batch (`write`) is gated by the close round, `context.audience_set` of `in_close` (the round the generation was opened in): it carries only the rows whose audience holds it, counted in `turn_count`/`round_count`, and a close without a round leaves empty.

## The history tools (`./history`, GH #893)

The model reads its own wall, deterministically and out of this hive's ledger alone: no model, no embedding, and never another model's wall. The schemas are the hive's menu answer (`./schemas` `CURATOR_OFFER`); the answer is a JSON object in the text of one `tool_result`.

| Tool | Arguments | Answer |
|---|---|---|
| `history_search` | `query`; `mode` `phrase` (default: the words in order, any case, any spacing), `exact` (case-sensitive) or `regex` (at most 200 characters); `since`/`until` (ISO-8601, a bare `until` date is the whole day); `kinds[]`; `limit` 1-20 (8); `context` 0-2 (0) | `hits[]` newest first: `id` (`#<12 hex>`), `seq`, `session_id`, `turn_id`, `at`, `kind`, `excerpt` (120 characters either side of the match), and with `context` the neighbours of the same session as `before`/`after`; `total_hits` (of the rows scanned), `scanned` (rows the round may see), `stopped_at_limit` (the page that filled `limit` was the last one read), `truncated_scan` and `cut_by` (`scan_budget` or `time_budget`) |
| `history_read` | `id` (`#<12 hex>`, bracketed, bare or the full hash) **or** `from_turn`/`to_turn` | `blocks[]` in wall order, each the stored element whole (`block`) with its row and `released`; `size`; for a range `skipped_history` |
| `history_outline` | `since` | `sessions[]` oldest first: `first_turn`, `last_turn`, `first_at`, `last_at`, `turns`, and `topics[]` (`name`, `from_turn`, `to_turn`, `open`) out of the `topic` marks (OR-KY-71: the open topic is the name of the newest mark with one and no later `end`, a nameless mark belongs to it; `from_turn` null = begun earlier); the newest 100 sessions of the newest `scan_budget` rows the round may see, `omitted_sessions` the rest, `truncated_scan` |

A refusal is an answer under the same call id, its code in the text (`error`) and in `hop.error_code`: `bad_arguments`, `bad_pattern`, `bad_range` (`since` after `until`, a turn range that runs backwards), `not_found` (an id or a turn this wall never carried), `ambiguous` (an id prefix that names two blocks; `candidates` lists them), `too_large` (`size`, `budget`; a range with more rows the round may see than `scan_budget` `block_count_at_least`, one whose raw text is over ten budgets `raw_size`, both refused before a body is read), `unknown_tool`, `ledger_error`, `missing_audience` (the call's context declares no `audience_set`; nothing is read). The model's own `history_*` calls and their answers are on the wall like every round, but no hits, no neighbours and no blocks of a range; by its id each is read whole. A read of a block TRIM released writes one `marks` row `reread` (the block's hash, the reading turn), once per block and turn; released is what the newest `scan_budget` `release` and `pin` marks of the block the round may see leave in `seq` order (GH #931).

**The row bound (GH #925, OR-BD-86).** Rows the round may not see count toward no budget, no page and no neighbour window, but every read stops at twice `scan_budget` rows in all. Where that leaves the answer open -- the visible rows it reached do not settle what the call answers on the same wall without the others -- the call answers in the cut form and shows nothing it read: a search `hits` [], `truncated_scan` true, `stopped_at_limit` false, `cut_by` `scan_budget` and a `detail`, no `scanned` and no `total_hits`; a `history_read` -- a turn range, or a read whose blocks' `release`/`pin` marks reach the bound -- `too_large` with a `detail` and `budget`, no `block_count_at_least`; an outline `sessions` [], `truncated_scan` true and a `detail`. The form is the same on every wall that reaches the bound, so hidden rows move one bit per call -- the bound was reached -- and never a count. It takes at least `scan_budget` hidden rows among the first twice `scan_budget` + 1 rows one read meets (of the `release`/`pin` marks of a read's blocks, more than `scan_budget` among their newest twice `scan_budget`); for the neighbours of a search with `context` (a side whose `context` + 4 nearest rows hold a hidden one is read again, one ledger round trip, the short sides sharing twice `scan_budget` rows) at least `scan_budget` / hits - `context` - 3 hidden rows of the hit's session on one side -- at the defaults with `context` 2: 245 with 20 hits, 620 with 8. Below that no answer shows a hidden row, its id or a word of it, and every number an answer carries counts rows the round may see, never all rows (`scanned`, `total_hits`, `block_count_at_least`, `size`, `turns`, `omitted_sessions`). Metadata channels (GH #932): since 1.4.0 every reader asks the ledger for the rows the round may see (`where audience_set covers <round>`; a round-less read asks for `[]` and `["*"]` rows of its own session), so a hidden row is never read -- page ends, `scanned`, the push and renewal windows and the per-turn `turn_index` hang on visible rows alone, and the row bound and its cut form are a second line that no longer fires on hidden rows. What stays: how long a read takes (the store still walks the hidden rows), the freshness check of a new session's handover, and the counts of `./stats` (OR-BD-6); where a rebuild cuts the window is no longer among them, the plan being one per round since GH #943 (a `release`/`pin` mark acts only on the windows of rounds that may see it and survives every rebuild of another round). `hop.turn_id` of `turn_write` is `<session_id>#<tag>-<index>`, `tag` the first 8 hex of the SHA-256 of the canonical round, the index counted per session and round. The round pays with that call's answer: a narrower `since`/`until` brings it back (a search also a smaller `limit` or no `context`, a range fewer turns, an outline a later `since`).

## Pure functions

`./policy` defines `curate_mark(window, limits)`, `amortise_after(window, rebuild_to, cost_in, cost_cached_in)`, `cost_cents(window, cached, limits)`, `estimate_tokens(value)`, `window_of(tokens_prompt, projected)` (GH #1038), `history_window(rows, params)` (the window between two rebuilds; short ids as the params' role says), `window_plan(rows, topic, trim, pins, prev, as_of_ms, slots, kept, cw)` (the plan a rebuild makes) and the constants `ROLES`, `KEEP_RECENT`, `COMPRESS_AT`, `REBUILD_TO`, `QUALITY_CAP`, `HORIZON`, `TIERS`, `SUMMARY_BUDGET` (= `SUMMARY_CHARS`), `KEEP_ROUNDS`, `STUB_TOOLS_AFTER`, `BROADCAST_MODE`, `RECALL_PUSH`, `RECALL_BUDGET`, `SHORT_IDS`, `SIDECAR_MAX_CHARS` at the top level, without I/O, loadable with `ast` like the collector's. `./schemas` holds `CURATOR_OFFER`: one list, an entry with `name` is a tool, one with `section` a sidecar section; `HISTORY_SCHEMAS` before it is a pure literal as well (the three history tools, spliced into the list). `./history` names what it reads of a call in `ARGS`.
